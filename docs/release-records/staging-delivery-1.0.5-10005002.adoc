[[smoke]]
== Installation and basic smoke test (reported by the CTO, 2026-11-27)

The CTO reports that one of the internal testers (Kevin) installed the new "Cadena Signer STAGING" application through TestFlight, launched it, completed the initial application setup and logged in successfully. On that basis the CTO declares the basic end-to-end iOS staging delivery acceptance criteria satisfied and requires no further tester confirmation for this deployment milestone.

This is a basic smoke test, not a test of wallet or DLC functionality. It shows that the delivered build installs, starts and can authenticate against the backend it was configured for. It does not cover wallet creation or recovery, device pairing, manual or automatic signing of funding, refund and CET transactions, notifications, upgrade from an earlier build, or any behaviour under load. The known pairing defect reported against the production-configured 1.0.4 build (issue #136) has not been re-tested. The report is a human observation: it is not backed by a log or screenshot in this repository, and it does not state what the Dashboard displayed.

[[credentials]]
== Credentials

* Only the three secrets of the environment `ios-hosted-signing-stg` were used, in the two steps designed for them. They had been provisioned by the maintainer before the merge (CTO decision R2) and verified by name and count only.
* The key file was removed, and this was recorded both before the verification steps and after the upload step (`key_file_removed` yes, `key_file_removed_after_upload_step` yes).
* After the run the maintainer removed the three secrets. A read of the GitHub API afterwards (names and counts only, never values) showed 0 secrets in `ios-hosted-signing-stg`, 0 in `ios-hosted-signing`, 0 repository Actions secrets, 0 Dependabot secrets and 0 organization secrets visible to the repository.
* The Apple Admin API key itself was **not revoked** by this; revoking it is a separate CTO decision.
* The CodeQL alert about the diagnostics workflow was dismissed by the CTO as "won't fix" before the first attempt; no workflow file or cache configuration changed afterwards.
